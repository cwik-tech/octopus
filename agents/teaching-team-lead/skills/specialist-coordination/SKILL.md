# Specialist Coordination

## Purpose

Orchestrate parallel pedagogical and technical reviews so specialists inform each other's work without waiting sequentially, and so their feedback addresses complementary dimensions rather than overlapping concerns.

## Coordination Strategy

### Parallel vs. Sequential

**Parallel Review (Recommended):**
- Both specialists receive the manual at the same time
- Each reviews independently, unaware of the other's findings
- Reviews complete in the same timeframe
- Synthesis happens after both reports arrive
- Benefit: Independent expert judgment; faster turnaround; natural divergence surfaces tensions and gaps

**Sequential Review (Only When):**
- The second specialist needs to respond to specific findings from the first
- The manual type requires one expert to validate before the other can assess (rare)
- Coordination risk: Specialists may duplicate effort or one specialist's framing may bias the other

### Specialist Request Framing

**Pedagogical Review Request Should:**
- State the learning goals explicitly ("Learners should understand X and be able to do Y")
- Name the target audience and prior knowledge assumptions
- Ask specifically about conceptual clarity, engagement, sequence, and prerequisite stepping
- Request feedback on whether learning goals are achievable with this material

**Technical Review Request Should:**
- State the technical scope and accuracy bar
- Ask specifically about completeness, precision, edge cases, and assumptions
- Request feedback on whether technical content is correct, up-to-date, and at the right depth for the audience
- Ask whether technical prerequisites are clearly stated

### Coordination Touchpoints

After both reviews arrive, look for:

1. **Direct contradictions:** Where pedagogical and technical feedback conflict ("Make this more concise for engagement" vs. "Add more technical detail for accuracy")
2. **Redundancy:** Where both specialists flagged the same issue from different angles
3. **Context gaps:** Where one specialist's finding makes sense of the other's concern
4. **Coverage asymmetry:** Where one specialist caught gaps the other missed

### Pre-Review Coordination Checklist

- [ ] Manual type is clearly identified for both specialists
- [ ] Learning goals and target audience are explicit (prevents specialists from assuming different readers)
- [ ] Pedagogical reviewer knows technical scope and accuracy bar
- [ ] Technical reviewer knows learning goals and pedagogical constraints
- [ ] Both specialists have the full manual and any supporting context
- [ ] Both specialists are asked to deliver feedback by the same deadline
- [ ] Both specialists understand they are reviewing in parallel (not sequentially)
- [ ] You have a plan for how to resolve predicted tensions (from classification step)

## Output

Coordination plan with:
- Parallel review routing (who gets what, when)
- Specialist-specific focus areas (to prevent silos)
- Predicted coordination touchpoints (conflicts, gaps, redundancies)
- Synthesis timeline and process
